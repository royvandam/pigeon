# Functional review

Reviewed commit `6c1a084` on 2026-10-25, after upload links and link
lifetimes were added in #24. The review looked at Pigeon from the point of
view of the people who use it: account holders moving files between their
devices, administrators, and people who receive a download or upload link. It
covered the explorer, uploads, the Share dialog, the upload link page, and
account self-service. Security, code quality, and performance were out of scope
except where a suggestion depends on them.

Unlike the other reviews, this one lists features and improvements rather than
defects. Each item has a value, an estimated effort, and a "Done when" check.

## Summary

Pigeon does its core job well: uploads keep their folder structure and publish
all at once, folders download as ZIPs, and download and upload links make it
easy to send and collect files without accounts. What it lacks is mostly
convenience around that core:

1. **Getting files in is slower than it needs to be.** Uploading means picking
   files through one of two inputs, and a large upload is lost if the
   connection drops.
2. **Links are hard to keep track of.** Links are visible only one item at a
   time, there is no quick way to open one on a phone, and owners do not learn
   when someone uploads through their link.
3. **Mistakes are permanent.** Deleting is immediate, and there is no way to
   act on several items at once.
4. **Users depend on administrators** for something as common as changing
   their password.

## F1. Drag-and-drop uploads

**Value:** High · **Effort:** Small · **Area:** Uploads · **Status:** Done in #PR

**Location:** [web/templates/uploads.html:6](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/uploads.html#L6),
[web/templates/uploads.html:20](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/uploads.html#L20),
[web/static/upload.js](https://github.com/royvandam/pigeon/blob/6c1a084/web/static/upload.js)

Uploading means choosing files with one input or a folder with another.
Dropping files or folders onto the page is what most people try first, and it
is the only way to upload files and folders together.

**Suggestion:** accept drops on the explorer's file list and on the upload link
page. Read dropped folders with `DataTransferItem.webkitGetAsEntry()` and send
each file with its relative path, as the folder input does; the server already
keeps folder structure. Highlight the drop area while dragging, and keep both
inputs for keyboard and screen-reader users.

**Done when:** dropping files, a folder, or both onto the explorer or the upload
link page uploads them with their folder structure, and the inputs still work.

**Resolution:** files and folders dropped anywhere on the explorer or the upload
link page upload at once, through the same quota check and progress display as
chosen files. Dropped folders are read through their entries, a batch at a
time, and each file is sent with its path from the dropped item; browsers
without entries upload the dropped files. A full-page overlay shows while files
are dragged over the page, dragging text is left alone, and drops during an
upload are refused with a message. The two pickers became one drop area with
**Choose files** and **Choose folder** buttons, since browsers pick either
files or a folder, and the progress panel shows only once an upload starts. Browser tests cover a mixed drop with nested folders read
in several batches, nested drag events, refused, empty, and oversized drops,
and the fallback.

## F2. Change your own password

**Value:** High · **Effort:** Small · **Area:** Accounts · **Status:** Open

**Location:** [web/templates/index.html:22](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/index.html#L22),
[pkg/account/store.go:192](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/account/store.go#L192)

Only an administrator can give a user a new password, as a generated
passphrase. Users cannot choose their own, or change a passphrase they were
given.

**Suggestion:** add a "Change password" form for signed-in users that asks for
the current password and the new one twice. Check the current password through
the sign-in rate limiter, apply the account package's password rule (at least
12 characters, at most 72 bytes), and, like an administrator's reset, end the
account's other sessions.

**Done when:** a user can change their own password, a wrong current password
counts as a failed sign-in attempt, and other sessions end.

## F3. An overview of active links

**Value:** High · **Effort:** Small · **Area:** Sharing · **Status:** Open

**Location:** [web/templates/shares.html:14](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/shares.html#L14),
[pkg/share/share.go:88](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/share/share.go#L88)

A link is visible only in its item's Share dialog, so finding out what is
public means opening every item. That matters more since upload links, which
let others write to the owner's storage.

**Suggestion:** add a "Shared links" page listing the account's active links:
the item, the kind, when it was created, and when it expires, with links to
the item and buttons to revoke. The share store needs a query listing an
account's links that have not expired. Tokens are stored only as hashes, so the
page cannot show URLs, only replace or revoke them.

**Done when:** a user can see all of their active links on one page and revoke
any of them there.

## F4. Sort the file list

**Value:** Medium · **Effort:** Small · **Area:** Explorer · **Status:** Open

**Location:** [web/templates/files.html:4](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/files.html#L4),
[pkg/server/explorer.go:43](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/explorer.go#L43)

The file list has a fixed order. In a folder with many items, finding the
newest or largest file means scanning the whole list.

**Suggestion:** make the Name, Size, and Modified headers sort the list, with a
second click reversing the order and folders kept first. Sort on the server
from a query parameter, so the order survives refreshes and works without
scripts, and mark the sorted column with `aria-sort`.

**Done when:** each column sorts in both directions, the order is kept when the
list refreshes after an upload, and screen readers announce it.

## F5. QR codes for links

**Value:** High · **Effort:** Small · **Area:** Sharing · **Status:** Open

**Location:** [web/templates/shares.html:14](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/shares.html#L14),
[web/static/shares.js](https://github.com/royvandam/pigeon/blob/6c1a084/web/static/shares.js)

Moving a file to a phone means copying a long URL to it somehow. Upload links
have the same problem in the other direction: the easiest way to get photos off
a phone is to open the upload page on it.

**Suggestion:** show a QR code next to a newly created link in the Share
dialog. Generate it in the browser with a small vendored encoder, so the token
never leaves the page, and render it as SVG to satisfy the content security
policy. Like the URL, it can only be shown right after the link is created.

**Done when:** creating or replacing a link shows a QR code that opens the link
when scanned, without any request to another site.

## F6. Resumable uploads

**Value:** Medium · **Effort:** Large · **Area:** Uploads · **Status:** Open

**Location:** [pkg/server/upload.go:138](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/upload.go#L138),
[pkg/files/upload.go](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/files/upload.go)

An upload is a single request. If the connection drops, or a laptop goes to
sleep, the whole transfer is lost and starts again from zero, which makes
multi-gigabyte uploads unreliable on Wi-Fi or mobile networks.

**Suggestion:** upload large files in chunks that the server appends to a
staged file, so a client can ask how much arrived and continue from there,
using the [tus](https://tus.io) protocol or a small chunked endpoint. Staged
chunks must count toward the quota checks, expire when abandoned, and still be
published all at once. Uploads through links need the same, scoped to the link.

**Done when:** an upload interrupted halfway resumes from where it stopped
after the connection returns, and abandoned uploads are cleaned up.

## F7. Previews

**Value:** Medium · **Effort:** Medium · **Area:** Explorer · **Status:** Open

**Location:** [pkg/server/download.go:41](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/download.go#L41),
[pkg/server/download.go:45](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/download.go#L45)

Every file is downloaded as an attachment, so checking a photo or a PDF means
downloading it and opening it elsewhere.

**Suggestion:** add a separate preview route for a fixed list of safe types:
common images, PDF, audio, video, and plain text. Serve them inline with their
real content type, a sandboxing content security policy, and `nosniff`, and
keep every other type as a download. Open previews in the explorer with the
download button beside them.

**Done when:** images, PDFs, media, and text open in the browser, other types
still download, and HTML or SVG files can never run scripts on Pigeon's
origin.

## F8. Limits per upload link

**Value:** Medium · **Effort:** Small · **Area:** Sharing · **Status:** Open

**Location:** [pkg/files/upload.go:109](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/files/upload.go#L109),
[pkg/share/share.go:88](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/share/share.go#L88)

Anyone with an upload link can upload until the owner's quota is full. A
lifetime limits how long, but not how much.

**Suggestion:** let the owner set an optional size limit, and optionally a
number of uploads, when creating an upload link. Store them with the link, add
what each upload publishes, and check the limit with the quota, under the
account lock. Uploaders see how much the link still accepts.

**Done when:** an upload that would exceed its link's limit is refused before
anything is published, and the limit is shown in the Share dialog and on the
upload page.

## F9. Notice of new uploads

**Value:** Medium · **Effort:** Small · **Area:** Sharing · **Status:** Open

**Location:** [pkg/files/upload.go:109](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/files/upload.go#L109),
[pkg/server/index.go:27](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/index.go#L27)

Owners cannot tell whether anyone has used their upload link without browsing
its folder, and cannot tell what arrived through the link and what they put
there themselves.

**Suggestion:** record, per upload link, when it was last used and how many
uploads and files arrived through it. Show this in the Share dialog and in the
links overview (F3), and mark folders that received uploads since the owner
last opened them.

**Done when:** an owner can see that, and when, files arrived through each of
their upload links.

## F10. Notes on upload links

**Value:** Low · **Effort:** Small · **Area:** Sharing · **Status:** Open

**Location:** [web/templates/upload_link.html:18](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/upload_link.html#L18)

The upload page shows only the folder's name. The owner cannot tell uploaders
what to send, and uploads from several people end up mixed together.

**Suggestion:** let the owner add a short message to an upload link, shown on
its page as plain text. Optionally ask uploaders for a name, and put each
upload in a folder with that name and the date.

**Done when:** an upload link can carry a message shown on its page, and, if
enabled, uploads are grouped by the name the uploader gave.

## F11. A trash bin

**Value:** High · **Effort:** Medium · **Area:** Safety · **Status:** Open

**Location:** [pkg/files/access.go:202](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/files/access.go#L202),
[web/templates/files.html:22](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/files.html#L22)

Deleting a file or folder removes it at once. A mistaken click on a folder can
destroy everything in it, with no way back short of a backup restore by an
administrator.

**Suggestion:** move deleted items into a per-account trash, in a reserved
folder like staged uploads, and remove them for good after a set time, such as
7 days. Show the trash with **Restore** and **Delete now**, and restore to the
original path or, if that is taken, a free name. Items in the trash keep
counting toward the quota, and their links stay revoked.

**Done when:** a deleted item can be restored for a set time, is removed
afterwards, and still counts toward the quota until then.

## F12. Actions on several items

**Value:** Medium · **Effort:** Medium · **Area:** Explorer · **Status:** Open

**Location:** [web/templates/files.html:22](https://github.com/royvandam/pigeon/blob/6c1a084/web/templates/files.html#L22),
[pkg/files/download.go:133](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/files/download.go#L133)

Moving, deleting, or downloading several items means doing it once per item.

**Suggestion:** add checkboxes to the file list and a toolbar to move, delete,
or download the selected items. Download several items as one ZIP. Apply moves
and deletions under one account lock, and report which items failed, if any,
rather than stopping at the first.

**Done when:** several items can be moved, deleted, or downloaded as one ZIP in
one action, and failures name the items they affect.

## F13. Search

**Value:** Medium · **Effort:** Medium · **Area:** Explorer · **Status:** Open

**Location:** [pkg/server/explorer.go:43](https://github.com/royvandam/pigeon/blob/6c1a084/pkg/server/explorer.go#L43)

Finding a file means remembering which folder it is in.

**Suggestion:** add a search box that finds items by name in the current
folder and below, case- and accent-insensitively, showing each result's folder.
Walk the account's files on request and stop at a fixed number of results; add
an index only if walking proves too slow for real accounts.

**Done when:** searching a name finds matching files and folders below the
current folder, with links to their folders, and stays fast for a typical
account.

## What to keep

These qualities make Pigeon pleasant to use; preserve them while adding
features:

- **Uploads all at once:** a batch appears together or not at all, and never
  replaces existing files.
- **Links without accounts:** recipients and uploaders need nothing but a
  link, and upload links never show what a folder holds.
- **A small, fast interface:** pages are rendered on the server, load only
  assets embedded in the binary, and never contact another site.
- **Plain errors:** messages say what went wrong and what to do next.
